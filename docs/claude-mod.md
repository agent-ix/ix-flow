# Claude workflow progress mod

The ix-flow Claude plugin includes a one-line band above the prompt:

```text
[release]  ✓ plan ━━ ⊙ build ──•── ○ review ━━ ○ ship
[release]  ✓ plan ━━ ◇ build ───── ○ review ━━ ○ ship · approval
[release]  ✓ plan ━━━━━ ✓ build ━━━━━ ✓ review ━━━━━ ✓ ship · done
```

While Claude works, a dot travels left to right along the active connector
(`•────`, `─•───`, `──•──`, `───•─`, `────•`, `─────`) every 450 ms.
The last frame has no dot, creating a pause before the next one-way sweep.
The line starts dark and brightens gradually with stage progression and completion.
The dot stays brighter than the line, with a subtle rise and fall in intensity
during each sweep. Upcoming stages stay dim.
Between turns the connector rests at `─────`. Approval gates pause it, and failed
commands show `⊗` until a successful command or a changed state version clears
the blockage. Animation indicates session activity, not a percentage or proof
that a worker is executing. Terminal phases stop the animation.

The bracketed prefix contains the workflow name, for example `[release]`.
Stage icons are `○` upcoming, `⊙` active, `✓` completed, `◇` awaiting approval,
and `⊗` blocked.

The complete declared stage list stays visible from start to finish. Completed
stages get `✓`; upcoming stages stay dim; the current stage has a green `⊙`
and a bold, soft-white label. Approval and blocked symbols stay yellow and red.
Connectors and the status area keep fixed widths, so stage transitions do not
shrink or rearrange the line. Branches that were not visited stay unchecked;
`|` separates stages without a direct edge, rather than implying a transition.
On narrow windows, labels shorten consistently for the entire run. Extremely
narrow windows may clip the line. Other mods' bands are preserved.

## Try the local build

Requires Claude Code 2.1.287 or newer and an ix-flow CLI build that includes
`progress`. From this repository:

```sh
make build
IX_FLOW_MOD_CLI="$PWD/bin/ix-flow.js" claude --plugin-dir "$PWD"
```

In Claude, type **`/flow-status demo`** to preview the animation immediately,
including while idle. This uses sample data and makes no CLI calls or state changes.
The demo progresses through **plan → build → review → ship**, spending about
5.4 seconds at each active stage. Its gradient changes gradually throughout,
and it stops with all four stages checked and `done`. Run `/flow-status demo`
again to replay the sequence.
Use `/flow-status off` to hide the preview.

To watch a real run, use `/flow-status RUN_ID`. For a custom state directory,
use `/flow-status RUN_ID /absolute/path/to/flows` (spaces in the path are fine).
Use `/flow-status off` to hide the line. Selection is local to this session and
is reset when the mod reloads. With no selected run, the band stays hidden.

When Claude invokes ix-flow through Bash, the returned run ID automatically
shows the bar and selects that run, replacing a demo or an earlier run. Both JSON
and ordinary `run: ID` output work. Literal `--state-dir` and `--config-root`
paths, including quoted spaces, are supported. If a shell expression computes
the location, use `/flow-status RUN_ID /absolute/state/path` explicitly.
Runs started in another terminal require explicit selection.

The mod polls `ix-flow progress RUN_ID --json` every two seconds, using an argument
vector rather than a shell. It only inspects runs: it never advances a phase,
acknowledges a gate, writes workflow state, or submits prompts. Query failures
replace the diagram with an error rather than displaying old state as current.
`IX_FLOW_MOD_CLI` can name another CLI executable; it must be one executable path,
not a shell command. Once released, the default uses `ix-flow` on PATH.

## API and verification

`ix-flow progress RUN_ID --json` returns the standard envelope with instance
data plus `phases` and `transitions`. It checks the definition hash, so a changed
or missing definition is reported rather than drawing an unverified graph.

```sh
claude plugin validate .
make test
make lint
make typecheck-mod
```

Official references: [Mods overview](https://code.claude.com/docs/en/plugins/mods/overview),
[drawing and timers](https://code.claude.com/docs/en/plugins/mods/interface), and
[API reference](https://code.claude.com/docs/en/plugins/mods/reference).
The band works on render surfaces that support mods; a headless session has no UI.

## TypeScript maintenance

The hooks module is `hooks/register.ts`; Claude loads it directly without a
JavaScript compilation step. `make typecheck-mod` checks the mod against the
vendored Claude Code **2.1.289** API declarations in `hooks/types/claude-code.d.ts`.
Workflow snapshots and rendered segments have explicit types, and CLI JSON is
validated before entering the renderer.

The declarations were generated by the installed Claude runtime when loading
this plugin. After updating Claude, load the plugin, then copy the generated
`.claude-plugin/types/claude-code/index.d.ts` to `hooks/types/claude-code.d.ts`,
run `make typecheck-mod`, and validate the plugin. Keep this snapshot unmodified;
Claude may extend or change its API between releases.
